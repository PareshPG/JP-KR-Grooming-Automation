## UPDATE (27 Oct 2026) - pipeline now adapts to ANY change in the number / order of columns
Request: "number of columns in report template increases or decreases in near future should not impact".

How it works (run_monthly_pipeline_JP.py Step 0c + remap_template_layout.py v2):
- Every run reads the template's header row 10 and the flat file's header row 10, and re-points a TEMP COPY of the template at the flat file's real layout by exact header text. The template file in the Report folder is never modified.
- Row limits are sized from the data every run (Respondent Data -> 1048576; AE tabs = largest month + 100 respondents, min 700; Worth it bound = 1.5x the table rows, min 10,000; bounds never shrink). Typed month names in Worth it formulas become $T$1; typed values in AE formula rows are restored to the formula.
- Respondent Data width = the flat file's width (no fixed 679 any more).
- If anything moved/added/removed, Layout_Change_Report.txt is written next to the template.
- STOP cases (clear message naming the column): a question the formulas read is missing/renamed in the flat file; a formula reference form the adapter cannot rewrite. If the client only re-worded a question, add a line "old header,new header" to Column_Aliases.csv in the Formatting folder and re-run.
- Adding, removing or moving questions the formulas do NOT read needs no action.

Tests (test_layout_changes.py, on the real Sept flat): 3 columns inserted; 2 unreferenced columns removed (narrower); referenced header renamed (STOPS, then passes with an alias line); referenced column dropped (STOPS); September grown to 1,101 respondents (AE rows grow to 1,300). ## FIX (27 Oct 2026, later) - Excel "We found a problem with some content ... Table from /xl/tables/table1.xml"
Cause: the client's template has a real Excel Table "RespondentsData" on the Respondent Data tab (A10:XY2263, 649 named columns, filter left on April 2026, two calculated-column formulas). The pipeline rewrote header row 10 to the new layout but the table still described the old one, so Excel repaired the file (and the macro runner's Workbooks.Open failed with error 1004).
Fix (remap_template_layout.py): the adapter now rebuilds the table every run - range A10:<last column><last data row>, one column per header (name = header text, formatting carried with the question), stale filter and calculated-column formulas removed. The pipeline checks the table against the header row and the row count before it writes anything and stops if they disagree. A header that is duplicated, empty or longer than 255 characters stops the run (an Excel table cannot hold it).
Note: pivot cache 13 reads the table by name (RespondentsData); its stored field list still has the old 649 fields until the pivot is refreshed in Excel.
